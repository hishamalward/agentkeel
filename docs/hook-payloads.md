# Hook payloads

Fixtures under `tests/fixtures/claude/` and `tests/fixtures/codex/` capture the host event shapes used by the adapters. Paths and sensitive identifiers are scrubbed. The fixtures are the contract exercised by tests; host versions can change their payloads, so update fixtures and parity tests when observed behavior changes.

Claude Code supplies JSON on stdin to configured hooks. PreToolUse hooks can block supported operations with exit status 2. Stop hooks may return a structured decision with `decision: "block"` and a reason. The payload's `stop_hook_active` indicates a retry; the task lifecycle itself is read from the persisted AgentKeel record. A task marked `cancelled` is retained without a delivery block. The Stop report is best-effort: an internal error is logged and exits successfully, so registration or trust is not proof of runtime enforcement. `task.py handoff` and `task.py finish` enforce the HTML checkpoint directly.

Codex supplies hook event JSON on stdin and consumes hook output according to its hook protocol. In particular, command exit status is not reliably exposed as verification evidence. AgentKeel does not claim that Stop enforcement is active merely because its hook is registered or trusted; use `task.py handoff` and `task.py finish` for the authoritative HTML check. See the fixtures and [host notes](hosts.md) for the observed support and limits.
