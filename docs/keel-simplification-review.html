AgentKeel, AgentSlots, MCPClerk: what to keep

The friction is designed in, not a bug: start always creates a worktree, each worktree has exactly one owning session, and the guard refuses every write outside that tree. Recommendation: retire AgentKeel's hooks and task machinery, remove MCPClerk, keep AgentSlots as the explicit tool it already is, and carry the two things that earned their place (sibling worktree per stream, HTML pages) as one script plus an AGENTS.md section. The revisions below were applied on 2026-10-21; see the status table at the end.

1. The system today

  • AgentKeel is a Claude Code plugin. Its four hooks run in every session and act in repositories listed in ~/.agentkeel/opted-in.json: one real repo (music_analytics) plus four fixtures.

  • Measured cost: 0.10–0.14 s per hook, two hooks per Bash call.

2. Why worktrees multiply

Four mechanisms, all in code. A–C are verified in both the installed 0.11.0 copy and the repo. D is a latent path bug that your AGENTS.md rule from 2026-10-04 papers over.

A · start always creates. There is no "use the worktree I am in."

hooks/task.py:118–128 · workspace.create() · identical in 0.11.0 and 0.12.0
if resuming or (size != "no-code" and not rec.get("worktrees")):
    ...
    else:
        owned = workspace.create(cwd, args.task, session, path=target, branch=args.branch, base=args.base)
  • Any task that is not no-code and has no worktree on its record gets a new branch and tree.
  • The session-start text and the guard's refusal text both lead with start.
  • resume exists but needs an absolute --worktree, a non-primary tree, a non-protected branch, and --from-session for every previous owner.

C · A worktree has exactly one owner. A second agent must take it from the first.

workspace.resume() 166–227 · record.ownership_problem() 139–153 · task-guard.decide(): "A transferred record cannot authorize edits"
  • The manifest .git/worktrees/<x>/agent-workspace.json stores one session.
  • resume demands --from-session for every current owner, then rewrites the manifest. The previous session now fails ownership_problem and the guard refuses all its writes.
  • Two agents in one tree is impossible by construction. ~/ma-android: six tasks in five days, each a handoff.

4. The eight questions

1 · Which capabilities are valuable and should remain?
  • Sibling worktree per stream, slug-derived branch
  • HTML spec and progress pages in doc/ and docs/; the review-page and debugging method texts
  • AgentSlots' slot-to-env mapping and simulator lock
  • The CI scripts and a PR-based ship path with a required check on main
2 · Which duplicate the harness?
  • Worktree creation and switching: EnterWorktree / ExitWorktree, Agent isolation: worktree
  • Destructive-command refusal: auto-mode $defaults, permissions.deny
  • Secret display: deny rules on cat .env, Read(**/.env)
  • MCP gating: per-tool prompts, permissions.ask, the auto-mode classifier
  • Stop report: branch and status already shown in context
  • MCPClerk config editing: claude mcp
3 · Is task/worktree authorization solving a real safety problem?
  • No. Permissions are declared by the agent "from your reading of the human's request". Self-granted permissions are ceremony, not a boundary.
  • The one real hazard, main auto-deploying to Railway, belongs on GitHub as a ruleset plus a native deny on git push … main.
  • Paid MCP calls belong on permissions.ask. Human-only commands are what the harness permission prompt already is.
4 · Which hooks or policies create more friction than value?
  • The write guard: "no task declared", shared-checkout refusal, other-worktree refusal, explicit-path commit rule
  • One-owner manifest and --from-session handoff
  • Fail-closed MCP bridge
  • Stop block on an "incomplete" HTML page
  • Destructive-op refusal overridden 69 times; git worktree add refusal that blocks fixing a bad path by hand
5 · Automatic, user-invoked, or removed?
  • Automatic: nothing beyond the harness and GitHub
  • User-invoked: scripts/workstream new|ls|done, agent-slots attach|release, gh pr create|merge, /review-page
  • Removed: all four hooks, task records, permissions, sizes, delivery validation, ship/finish logic, MCPClerk
6 · Fewer tools, scripts, or conventions?
  • Three tools become one scripts/workstream script, AgentSlots unchanged behind it, an AGENTS.md section, two skill files. No new framework.
7 · What breaks if removed?
  • Nothing that runs. Agents can write in the primary checkout when you choose; the ruleset guards main.
  • finish no longer releases slots or removes trees: workstream done does.
  • Task-record history stays on disk; nothing reads it. Five tasks parked in "handoff" need no action.
  • The AGENTS.md managed block must be rewritten or sessions keep being told to run task.py.
8 · Smallest design that supports the workflow?
  • Section 6: conventions + one script + native permission rules + a GitHub ruleset. Zero hooks.

6. The minimal design

Everything automatic is something the harness or GitHub already does. Everything else is a command you or an agent runs on purpose.

Automatic (no new code)

  • Claude Code permission prompts and auto-mode classifier for destructive git, deploys, paid calls.
  • permissions.deny / ask rules in ~/.claude/settings.json (mockup below).
  • GitHub ruleset on main: PR required, agentkeel-checks status required, no force push. Must exist before Stage 1 is relied on.
  • Branch and cwd shown by the harness.

User-invoked

  • scripts/workstream new <slug> [--type feat] [--service web|db|queue|mobile …] [--prepare]: sibling tree, slug branch; a slot only for the services named, chosen by the agent from the ask.
  • scripts/workstream ls, scripts/workstream done <slug>: list; release slot and remove when merged and clean.
  • scripts/agent-slots … directly for runtime-only changes.
  • gh pr create, gh pr merge --auto --squash.
  • /review-page and the debugging skill, as text.

10. Verified vs assumed

Verified

  • All cited code paths read in both the installed 0.11.0 copy and the 0.12.0 repo. start() and workspace.py are identical in both.
  • Drift: task.py 98 differing lines, task-guard.py 17, opt-in mechanism changed.
  • Hook latency 0.10–0.14 s, measured with a probe payload. Guard active in music_analytics: a Write probe returned "no task is declared".
  • Task records, overrides, stop-reports, opted-in list, plan-gates: read directly.
  • No nested worktree on disk; live trees are flat siblings. ~/ma-provider-refresh-resilience is not a git tree.
  • MCPClerk: no catalog or policy under ~/.mcpclerk; bridge routes every mcp__* tool and fails closed.
  • AgentSlots ↔ Keel: exactly two call sites, both release.
  • Harness: EnterWorktree / ExitWorktree descriptions read this session; auto-mode soft_deny includes $defaults and railway deploy.

Assumed or unverified

  • Transcript counts are upper bounds inflated by sessions that read the source.
  • Whether nesting (cause D) ever happened: the code allows it and your 10-04 rule forbids it, but no nested tree or transcript path was found.
  • GitHub branch protection on main: gh is not authenticated here.
  • Whether subagents share the parent's session_id in hook payloads. If not, every subagent in an opted-in repo is blocked on its first write today.
  • That the auto-mode classifier treats git push … main and force pushes as destructive by default; the deny rules do not depend on it.
  • AgentSlots usage share: 314 transcripts mention it, but most frequent commands are agents auditing the tool itself.
